## Overview

“月光茧 / Moonlight Cocoon” is a romantic premium website system for an AI boyfriend, virtual companion, and otome-style emotional relationship product. It should not look like a cold AI productivity tool, and it should not directly copy a dense mobile game interface. The website is a brand landing page: clear, spacious, readable, and conversion-oriented, but still emotionally rich.

The visual language is built around **moonlight, cocoon silk, blue night, soft stars, butterflies, pearl glass, a human companion presence, and an approved atmospheric background artwork**. The page should feel like entering a quiet moonlit room where someone is waiting for you. It must be romantic and delicate without becoming overly ornate.

**Key Characteristics:**

- Blue starry-night palette with layered moonlight gradients, not a flat dark-blue background.
- A clearly recognizable glowing “月光茧” symbol as the brand mark.
- Human-like male companion visual as the emotional center; robot mascots are not suitable for the hero.
- Sparse but visible star dust, silk-like arcs, butterfly lights, and moon-white petal particles.
- Pearl-like glass panels with subtle radial highlights, thin luminous borders, and soft inner glow.
- Approved background artwork used as the webpage base, with a global 6px blur treatment.
- Interactive floating particles above the background and below the UI, with mouse-drag response.
- Simple web structure: hero → four feature cards → relationship journey → download CTA.
- More romantic than SaaS, more restrained than a mobile game, more luminous than a plain dark site.

## Background Artwork Asset

The approved moonlit butterfly banner artwork is part of the design system and should be treated as the **default webpage background** for the homepage and other major brand pages.

### Background Artwork Role

This artwork is not just decoration. It is the emotional foundation of the page. It provides:
- the moonlit fantasy atmosphere;
- white glowing butterflies as an otome cue;
- soft particles and moonlight for romantic depth;
- subtle floral elements for delicacy;
- a soft visual stage for frosted-glass UI.

### Visual Description

The approved background should read as:
- a wide romantic moonlit banner;
- deep-to-light blue night sky;
- a bright moonlight source in the upper-right;
- translucent white glowing butterflies;
- silk-like moonlit trails;
- a small amount of floating petal / dust particles;
- subtle white flower clusters near the lower right or edge zones;
- a large clean open center area for UI placement.

### Usage Rules

- Use this artwork as the **bottom-most visual layer**.
- Set the image to `background-size: cover`.
- Preferred positioning: `center center`.
- Use `background-repeat: no-repeat`.
- Apply `filter: blur(6px)` to the background image layer.
- The blur should soften detail slightly so the UI remains legible, but it must not destroy the moonlight and butterfly shapes.
- UI panels, cards, and text sit above this layer and use glassmorphism for separation.
- The artwork should not scroll at a noticeably different speed unless subtle parallax is intentionally implemented.

### Implementation Reference

```css
.page-bg-artwork {
  position: fixed;
  inset: -12px;
  background-image: url("/assets/backgrounds/moonlit-butterfly-banner.png");
  background-size: cover;
  background-position: center center;
  background-repeat: no-repeat;
  filter: blur(6px);
  transform: scale(1.03);
  z-index: 0;
  pointer-events: none;
}
```

Notes:
- The slight `scale(1.03)` prevents blur edges from showing.
- Keep the blur on the artwork layer only, not on the entire page.
- Additional gradient overlays can still be added above the artwork if needed.

## Interactive Particle Layer

A floating particle layer must be added above the blurred background artwork and below all foreground UI. This layer makes the page feel alive and romantic without becoming game-like.

### Role

The interactive particle layer should:
- make the background feel breathable and dimensional;
- connect the user’s movement with the atmosphere;
- reinforce moonlight, butterfly, and magic-dust feelings;
- add gentle interactivity appropriate for an otome companion product.

### Visual Style

Particles should be:
- soft moon-white, ice-blue, or pale blue-white;
- circular or slightly petal-like;
- low-opacity with light bloom;
- varied in size;
- sparse enough to avoid noise.

Recommended particle size:
- small: `2px–4px`
- medium: `5px–8px`
- accent: `9px–14px` very few only

Recommended opacity:
- `0.20–0.65`

Recommended glow:
- subtle outer glow rather than hard edges

### Motion Style

Particles should:
- float upward or diagonally with low speed;
- move with slight parallax drift;
- respond gently to mouse movement;
- not bounce or behave like a game particle system.

### Mouse Drag Interaction

When the user drags the mouse:
- nearby particles should be softly attracted, repelled, or displaced along the drag path;
- the effect should feel like brushing through moonlight dust;
- the motion should be delayed and eased, not sharp;
- particles should gradually settle back into ambient drift.

Recommended interaction behaviors:
- hover: mild displacement or glow lift;
- drag: stronger local movement and trail response;
- release: particles slowly relax back into natural motion.

### Interaction Intensity

Keep interaction subtle:
- response radius: `80px–180px`
- displacement distance: `8px–28px`
- easing: `0.08–0.16`
- return duration: `0.8s–2.2s`

The interaction should feel **poetic**, not playful or chaotic.

### Layer Placement

```css
.page-bg-artwork    -> z-index: 0
.bg-gradient-overlay -> z-index: 1
.particle-layer      -> z-index: 2
.page-ui             -> z-index: 10
```

### Canvas / DOM Recommendation

Implementation can use:
- HTML canvas;
- WebGL particles;
- lightweight DOM particles with transform animation.

Preferred choice:
- `canvas` for performance and smooth mouse-drag interaction.

### Example Layer Style

```css
.particle-layer {
  position: fixed;
  inset: 0;
  z-index: 2;
  pointer-events: auto;
}
.page-ui {
  position: relative;
  z-index: 10;
}
```

## Visual Theme & Atmosphere

The atmosphere should be **blue, moonlit, soft, intimate, and slightly fantastical**. Minimalism is only the structure; the mood still needs visual richness. Empty dark-blue space should be avoided. Every viewport should contain at least one atmospheric cue: a moonlight halo, a soft mist gradient, a star cluster, a butterfly light, or a silk arc.

The design should feel like:
- a quiet night sky seen through moonlit glass;
- an intimate AI companion world rather than a productivity dashboard;
- a refined otome website rather than a game event page;
- soft luxury rather than childish fantasy.

Do not make the page overly dark, overly flat, or overly functional. The target is **romantic premium**, not generic dark-mode SaaS.

## Glassmorphism Application

All major UI elements should sit on top of the background artwork using frosted glass styling. The UI should feel like it is floating above the moonlit scenery.

### Core Rule

- Background artwork: blurred `6px`
- UI cards / panels: use `backdrop-filter: blur(16px–20px)`
- Chat bubbles / small cards: `blur(14px–18px)`
- Stronger panels like download CTA: can use slightly brighter fill and stronger border glow

### Frosted Panel Principle

Foreground UI should never be opaque solid blocks unless needed for QR codes or primary CTA pills. The UI must preserve some sense of the background image underneath.

Example:
```css
.romantic-glass-panel {
  background: rgba(180,215,255,0.18);
  border: 1px solid rgba(235,248,255,0.50);
```

## Motion

Motion should be slow, romantic, and subtle.

- Background particles drift slowly with low-speed parallax.
- Particles respond to mouse hover and drag with soft displacement.
- Star twinkle: `3–6s`, opacity only.
- Butterfly drift: `6–9s`, 8–16px vertical movement.
- Moon glow breathing: `8–12s`, opacity 0.36–0.50.
- Silk arcs shimmer gently with low opacity.
- Character card can float by 2–4px.
- Cards hover: translateY(-4px), slightly brighter border.
- Button hover: translateY(-2px), glow +10%.

Avoid:
- bounce;
- confetti;
- fast neon animation;
- reward burst effects;
- game-like pop-ups.

## Responsive Behavior

### Breakpoints

| Name | Width | Key Changes |
|---|---:|---|
| Small phone | ≤ 420px | Single-column layout, hero title 34–38px, CTAs stacked |
| Phone | 421–640px | Character below copy, feature cards 1 column |
| Tablet | 641–1024px | Hero 1 column or reduced 2 column, feature cards 2 columns |
| Small desktop | 1025–1280px | Full layout, reduced hero visual scale |
| Desktop | 1281–1440px | Full layout, content max-width 1280px |
| Wide desktop | ≥ 1441px | Content centered, atmosphere extends full viewport |

### Mobile Rules

- Reduce decorative density by 30–40%, but keep the moonlight artwork visible.
- Keep butterfly accents small; avoid blocking text.
- Character image should move below the hero copy or become a cropped portrait.
- Cards collapse to one column.
- CTA buttons stack vertically with full width.
- Navigation collapses to logo + menu button + primary CTA.
- Background artwork blur remains `6px`, but particle count should be reduced for performance.
- Mouse drag interaction degrades gracefully to passive drifting or touch-follow behavior.

### Touch Targets

- CTA buttons: minimum 48px height.
- Icon buttons: minimum 44 × 44px.
- Platform buttons: minimum 40px height on desktop, 44px on mobile.

## Accessibility

- Ensure body text on glass panels remains readable with enough contrast.
- Add dark scrim behind text if placed over bright moonlight or character imagery.
- Avoid using glow as the only indicator of active state.
- Provide focus states for buttons and links.
- Decorative stars, butterflies, petals, arcs, and particles should be marked as decorative in implementation.
- Respect `prefers-reduced-motion` by disabling particle drag response, floating, and shimmering animations when requested.
- If particles are interactive, ensure they do not block button clicks or text selection inside the UI layer.

## Iteration Guide

1. If the page looks too cold, increase moonlight glow and add warm pearl highlights before adding more modules.
2. If the page looks too empty, strengthen the approved background artwork, particle layer, mist, stars, silk arcs, and butterflies — not more text.
3. If the page looks too game-like, reduce badges, icons, and dense UI frames; keep only poetic cues.
4. If the page looks too SaaS-like, replace robot/abstract assistants with a human-like male companion visual.
5. If the page looks too purple, return to deep blue, mist blue, ice blue, and moon white.
6. If cards look flat, add radial pearl highlights, inner glow, and subtle top highlight lines.
7. If the logo is weak, enlarge the 月光茧 symbol and add moon-white / ice-blue glow.
8. Always refine one layer at a time: background artwork → particle layer → hero character → glass cards → CTA.
